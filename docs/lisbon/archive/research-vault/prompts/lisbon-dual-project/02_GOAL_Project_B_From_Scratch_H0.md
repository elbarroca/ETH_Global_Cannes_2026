## Trust And Scope

Agents have no keys or payment authority. ## Agentic Problem Contract

- **Problem:** determine whether an unstructured vendor invoice is actually payable against a purchase order, delivery evidence, vendor identity, treasury policy and prior receipts.
- **Why AI:** semantic matching, incomplete evidence and exception reasoning cannot be reduced to fixed fields without losing the core failure cases.
- **Evidence Agent:** isolated reconciliation; outputs `PAY | REFUSE | REVIEW`, evidence hashes and gaps.
- **Risk Agent:** independent adversarial review; outputs `CLEAR | VETO | REVIEW` and conflict hashes.
- **Settlement Agent:** sees normalized verified intent only; outputs `EXECUTABLE | BLOCKED` plus a bounded route.
- **Recovery Agent:** sees persisted network IDs/status only; outputs `PAID | PENDING | RECOVERY_REQUIRED`; cannot create an intent.
- **Deterministic boundary:** `PAY_AUTHORIZED` requires Evidence=`PAY`, Risk=`CLEAR`, Settlement=`EXECUTABLE`, all proofs valid, policy green and human signatures.
- **Forbidden:** one call role-playing agents, copied outputs, shared mutable agent state, model majority authorization, agent-held keys, veto bypass, or replacement payment after ambiguity.

## Required Tests

- Valid obligation -> Evidence=`PAY`, Risk=`CLEAR`, Settlement=`EXECUTABLE`; three verified runs, green quorum, one claim/schedule/effect/receipt.
- Agent disagreement/veto -> `REFUSE` or `REVIEW`; no claim, approval, signing or payment preparation.
- Reused run/output/prompt across roles -> fake multi-agent rejection before quorum.
- Agent timeout/cancellation -> durable review state; late output cannot authorize.
- Prompt injection in invoice -> cannot modify role/system/tool policy or reach Settlement context as instructions.
- Veto bypass attempt -> deterministic quorum rejects despite Evidence=`PAY`.
- Tampered/missing/wrong 0G proof -> no HTS, schedule, signing, bridge or swap preparation.
- Duplicate/concurrent/restart -> same intent/schedule/message/destination identifiers and one public effect.
- Stale quote/deadline/slippage/recipient -> destination refuses before swap; funds remain recoverable.
- Axelar delay/duplicate/out-of-order callback -> one process or durable pending state.
- Partial source success/destination failure -> no false payment status; explicit retry/recovery/refund state.
- Prompt injection/malformed agent output -> validation failure or `REVIEW`, zero value.
- Sponsor unavailable -> affected track cut honestly, no mock receipt.
- Fresh clone and two deterministic demo replays.
